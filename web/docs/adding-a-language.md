# Adding a language to Saral

This guide adds a complete new language to Saral: the website interface and
every published lesson. It uses Tamil (`ta`) as the example. Replace `ta`,
`Tamil`, and `ta-IN` with the language you want to add.

## Before you start

Choose:

- an ISO-style two-letter language code, such as `ta`;
- the language's name written in that language, such as `தமிழ்`;
- its JavaScript date locale, such as `ta-IN`.

The interface text lives in one place:

[`web/src/lib/i18n.ts`](../src/lib/i18n.ts)

Lesson translations are generated separately by the Python pipeline. Do not
put lesson text in the UI catalog.

## 1. Add the frontend language code

In `web/src/lib/i18n.ts`, add the code to `SUPPORTED_LANGUAGES`:

```ts
export const SUPPORTED_LANGUAGES = ["en", "hi", "bn", "ta"] as const;
```

This one change updates the frontend's language type, route generation, content
schema, and language selector. The selector displays the native `name` from the
locale object added in the next step.

## 2. Generate the UI translation from English

Use only the `LOCALES.en.ui` object in `web/src/lib/i18n.ts` as the source. Do
not ask a model to translate Astro, TypeScript, HTML, URLs, article Markdown,
or article tags.

Use a prompt like this with your chosen translation model:

```text
Translate the following Saral interface-text object from English to Tamil.

Saral serves elderly people, people with disabilities, and people who are not
confident with technology. Use short, warm, everyday Tamil. Avoid technical
jargon and overly formal wording.

Rules:
- Return the values for every key exactly once.
- Do not rename, remove, reorder, or add keys.
- Do not translate Saral.
- Preserve {page} and {count} exactly, including their braces.
- Do not add Markdown fences, notes, explanations, or frontmatter.
- Keep labels short enough for buttons and navigation.

English source object:
<paste LOCALES.en.ui here>
```

The generated result should be an object body with the same keys as `en.ui`.
Review it before adding it to the repository. In particular, check the short
labels for Home, All topics, sharing, theme controls, previous/next lesson, and
the tagline.

## 3. Add the reviewed UI locale

Add a `ta` entry inside `LOCALES`, alongside `en`, `hi`, and `bn`:

```ts
ta: {
  name: "தமிழ்",
  dateLocale: "ta-IN",
  ui: {
    siteTitle: "…",
    siteDescription: "…",
    tagline: "…",
    aiDisclosure: "…",
    // Paste every remaining reviewed key from the generated object.
    pageOf: "{page} / {count}",
  },
},
```

`pageOf` is a normal translated string. It must retain both `{page}` and
`{count}` so Saral can insert the numbers at runtime.

TypeScript will point out any missing UI key. Do not work around that error by
copying English values unless that is a deliberate product decision.

## 4. Enable lesson translation in the Python pipeline

Add the code and language name to `Translator.LANGUAGES` in:

[`llm/translator/translator.py`](../../llm/translator/translator.py)

```py
LANGUAGES = {
    "bn": "Bengali",
    "hi": "Hindi",
    "ta": "Tamil",
}
```

Add the code to both lists that decide which Markdown translation files must
exist:

- `TRANSLATION_LANGUAGES` in [`llm/exporter.py`](../../llm/exporter.py)
- `TRANSLATION_LANGUAGES` in [`tools/rerun_topics.py`](../../tools/rerun_topics.py)

For example:

```py
TRANSLATION_LANGUAGES = ("bn", "hi", "ta")
```

These changes ensure a Tamil file is written to:

```text
web/src/content/articles/ta/<article-slug>.md
```

## 5. Generate missing translations for existing articles

After the configuration changes, regenerate translations for previously used
topics:

```bash
python tools/rerun_topics.py --translations --yes
```

To translate only one existing article:

```bash
python tools/rerun_topics.py --translations --topic "How phones use AI" --yes
```

The tool preserves the existing English article and only creates the missing
language Markdown files. It also creates a backup before changing files.

New articles generated by `python -m llm.main` will include the new language
automatically once the three Python configuration locations above are updated.

## 6. Check before publishing

- The language appears in the header selector using its native name.
- The homepage, tag page, article controls, sharing text, tagline, and footer
  are all in the new language.
- The language homepage (`/ta/`) and a lesson (`/ta/articles/<slug>/`) exist.
- Tags link to the matching translated tag pages.
- The new Markdown files contain translated title, summary, tags, image alt
  text, and lesson body.
- `{page}` and `{count}` appear correctly on paginated pages.

Finally, commit the new locale, translated Markdown, and any generated assets
that should be deployed.

## Current limitation

The frontend locale catalog is centralized. The backend language list is still
present in the three Python locations named above, so update all three together
until those are consolidated in a future refactor.
